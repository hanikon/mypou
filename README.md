# Капля (Kaplya)

Telegram Mini App: виртуальный питомец-«капля» и крестики-нолики на двоих.
Название временное и меняется в `packages/shared/src/config.ts`.

Персонаж, графика (SVG в коде) и звуки (синтез через WebAudio) оригинальные.

## Статус

| Этап | Что | Статус |
|---|---|---|
| 0 | Каркас монорепо, CI | ✅ |
| 1 | Питомец офлайн: показатели, комнаты, магазин, CloudStorage | ✅ |
| 2 | Worker + Supabase, проверка initData, серверные монеты | ✅ |
| 3 | Друзья, гости, подарки, уведомления | ✅ |
| 4 | Крестики-нолики онлайн и против компьютера | ✅ |
| 5 | Cron-«будильник» для Supabase | ✅ |
| 6 | Telegram Stars (опционально) | отложено |

## Структура

```
apps/web/            фронтенд: Vite + Preact + TypeScript (Cloudflare Pages)
apps/worker/         бэкенд: Cloudflare Worker — API, бот grammY (webhook)
supabase/migrations/ SQL-миграции
  src/pet/           SVG-персонаж и слои вещей
  src/rooms/         комнаты и действия (еда, мыло, свет, игра)
  src/games/         мини-игры
  src/ui/            HUD, навигация, магазин, кнопки Telegram
  src/state/         состояние и сохранение (CloudStorage / localStorage)
  src/i18n/          строки ru / en
packages/shared/     общая логика для клиента и сервера + тесты
  src/catalog/items.json   каталог предметов (цены, SVG-слои)
```

## Локальный запуск

Нужен Node.js 22 (см. `.nvmrc`).

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты игровой логики
npm run typecheck
npm run build      # сборка в apps/web/dist
```

Вне Telegram приложение работает как обычный сайт: сохранение в `localStorage`, кнопки Telegram заменяются обычными.

## Как играть (этап 1)

- **Кухня**: перетащи еду из полки ко рту питомца.
- **Ванная**: потри питомца мылом.
- **Спальня**: выключи свет, и питомец уснёт и восстановит энергию.
- **Игровая**: «Поиграть» поднимает настроение, а «Пузыри» — мини-игра за монеты.
- **Магазин**: еда, цвета, шапки, очки, одежда, узоры стен. Невыбранную вещь можно примерить, купленную надеть или снять тапом.

Показатели (сытость, чистота, энергия, настроение) падают со временем и пересчитываются по метке последнего визита. Ниже 5 они не опускаются: питомец грустит, но не «умирает».

## Друзья (этап 3)

- **Пригласить:** «Друзья» → «Пригласить друга». Ссылка вида `https://t.me/<bot>/<app>?startapp=invite_<код>`. Друг открывает её, и вы становитесь друзьями. Ссылка через бота (`/start invite_<код>`) тоже работает.
- **В гости:** видно питомца друга, его можно покормить едой из его холодильника (до 10 раз в час).
- **Подарки** за свои монеты, не больше 3 в сутки. Списание, вручение и уведомление проходят одной транзакцией.

## Крестики-нолики (этап 4)

Игровая → «❌⭕ Крестики-нолики».

- **Против компьютера** (minimax): «лёгкий» часто ошибается, «сложный» не проигрывает никогда. Это доказано тестом, который перебирает все партии. Игра идёт на устройстве и монет не даёт.
- **С другом:** кто создал партию, играет X и ходит первым. С одним другом одновременно идёт одна партия.
  - Каждый ход проверяет сервер: чей ход, свободна ли клетка, закончена ли партия, номер хода. Двойное нажатие или вторая вкладка не сломают партию.
  - Экран партии опрашивает сервер раз в 2 секунды, пока приложение на экране.
  - Соперник получает «твой ход» с кнопкой, которая открывает сразу эту партию (`startapp=game_<id>`). Если соперник смотрит партию прямо сейчас, уведомления не будет.
  - За победу +15 монет, но только за первые 5 побед в сутки. Победа сдачей монет не даёт, иначе монеты можно было бы перекидывать друг другу.
  - Счёт между вами и последние партии видны в меню игры.

## Уведомления: как сделано, чтобы точно доходили

1. **Очередь в базе (outbox).** Событие сначала записывается в таблицу `notifications`, потом отправляется. Для подарка запись делается в той же транзакции, что и подарок. Сбой отправки не теряет уведомление.
2. **Отправка сразу и повторы.** Worker отправляет сообщение сразу после события. Cron раз в 5 минут досылает всё, что не ушло:
   - **429** (Telegram просит подождать): ждём `retry_after`;
   - **сеть или 5xx**: паузы 1, 2, 4… минут (не больше часа), до 10 попыток;
   - **«зависшие»** (Worker упал во время отправки): возвращаются в работу через 2 минуты.
3. **Без дублей.** «Голоден» приходит не чаще раза в 12 часов, «гость» — раз в 3 часа от одного друга.
4. **Право писать.** Бот может писать только тем, кто ему разрешил. Учитываются `/start` в боте, флаг `allows_write_to_pm` и запрос `requestWriteAccess()`: Mini App спросит один раз, ещё есть кнопка в настройках. Если бота заблокировали (403 или событие `my_chat_member`), флаг снимается, а настройки показывают «Бот пока не может писать».
5. **Проверка.** «⚙️ → Проверить уведомления» отправляет тестовое сообщение и сразу показывает результат.
6. **Отключение.** В Mini App (⚙️) или командой `/settings` в боте: все уведомления или отдельно «голод», «друзья», «твой ход».

Посмотреть очередь: Supabase → Table Editor → `notifications`. Колонки `status` (`pending`, `sent`, `dead`, `skipped`) и `last_error` показывают, что произошло с каждым уведомлением.

## «Будильник» Supabase (этап 5)

Бесплатные проекты Supabase засыпают примерно через неделю без активности. Worker держит проект активным двумя способами:

- **«Будильник»:** cron `17 6 */2 * *`, раз в 2 дня в 06:17 UTC. Обновляет единственную строку `heartbeat` и пишет в лог `heartbeat: ok (cron) beat_at=…`. При ошибке делает ещё 2 попытки с паузой.
- Дополнительно каждые 5 минут к базе обращается cron уведомлений.

### Как проверить, что «будильник» работает

1. Открой `https://kaplya-api.<subdomain>.workers.dev/health`. Ответ вида `{"ok":true,"supabase":"ok","lastHeartbeat":"…","hoursAgo":5,"source":"cron"}`: `hoursAgo` должен быть меньше 50, `source` равен `cron`. Сразу после настройки там `init`, пока cron не сработал впервые.
2. Cloudflare → Worker → Settings → **Trigger Events**: в списке два расписания, `*/5 * * * *` и `17 6 */2 * *`.
3. Cloudflare → Worker → **Logs**: поиск `heartbeat` покажет строки `heartbeat: ok (cron)`.
4. Supabase → Table Editor → `heartbeat`: в `beat_at` свежая дата.

Если `/health` отвечает `"supabase":"unreachable"`, значит проект спит или не настроены ключи.

### Если проект всё же уснул

1. [supabase.com/dashboard](https://supabase.com/dashboard) → проект (помечен **Paused**) → **Restore project**. Восстановление занимает несколько минут, данные сохраняются.
2. Если кнопки нет: Supabase разрешает восстановить приостановленный бесплатный проект только в течение ограниченного срока (сейчас 90 дней). Позже доступна лишь выгрузка данных. Точные условия смотри в панели.
3. После восстановления открой `/health` и убедись, что вернулось `"supabase":"ok"`. Ключи и URL не меняются, Worker перенастраивать не нужно.

## Два режима

- **Серверный** (открыто в Telegram и задан `VITE_API_URL`): всё хранится в Supabase. Клиент показывает результат сразу, но сервер пересчитывает каждое действие по тем же правилам (`packages/shared`) и при расхождении откатывает. Монеты начисляет только сервер.
- **Офлайн** (браузер или нет `VITE_API_URL`): сохранение в Telegram CloudStorage или localStorage. Одно значение CloudStorage ограничено 4096 символами, поэтому длинный JSON режется на ключи `pet_0…pet_N`, а `pet_n` хранит их число.

## Безопасность сервера

- Каждый запрос несёт `Authorization: tma <initData>`. Worker проверяет HMAC-подпись (ключ из токена бота) и возраст `auth_date` (не старше 24 ч). ID пользователя берётся только из проверенных данных.
- Клиент присылает лишь намерение (`{type: 'buy', item: 'h_crown'}`). Цены, остатки и монеты считает сервер. Неизвестные поля и действия отбрасываются.
- Мини-игра: сервер запоминает время старта. Результат принимается только через 18–180 с, очки обрезаются до правдоподобных, монет из игр не больше 150 в сутки.
- Сохранение атомарное, с проверкой версии: параллельные запросы не дублируют монеты и еду.
- Лимит: 60 запросов в минуту на пользователя.
- RLS включён во всех таблицах без политик. Ключи `anon`/`authenticated` не видят ничего, работает только `service_role` из Worker.
- CORS разрешён только для `WEB_ORIGIN` (и `localhost` для разработки).
- Webhook бота проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.

## Пошаговая настройка

Порядок: бот → Supabase → Worker → Pages → Mini App. Секреты храни в менеджере паролей и не присылай в чаты.

### 1. Бот в @BotFather

`/newbot` → имя и username. Получишь токен (`BOT_TOKEN`).

### 2. Supabase

1. [supabase.com](https://supabase.com) → New project (Free). Регион поближе, пароль БД сохрани.
2. **Миграции.** SQL Editor → New query → вставь содержимое `supabase/migrations/20261010000000_init.sql` → Run. Новые миграции из этой папки применяй так же, по порядку имён.
   - С компьютера можно через CLI: `npx supabase link --project-ref <ref>` и `npx supabase db push`.
3. **Ключи.** Project Settings → API Keys:
   - Project URL → `SUPABASE_URL`;
   - `service_role` (Legacy API Keys) или новый **secret** key → `SUPABASE_SERVICE_ROLE_KEY`. Этот ключ обходит RLS. Он нужен только Worker, во фронтенд и в git его не клади.
4. Проверка: Table Editor показывает таблицы `users`, `pets`, `inventory`, `friendships`, `games`, `gifts`, `heartbeat`, `rate_limits`, на каждой значок RLS enabled.

### 3. Worker (API и бот)

1. Cloudflare → Workers & Pages → Create → **Import a repository** → `mypou`.
2. Настройки сборки:
   - Project name: `kaplya-api` (должно совпадать с `name` в `apps/worker/wrangler.toml`)
   - Root directory: `/`
   - Build command: `npm ci`
   - Deploy command: `npx wrangler deploy --config apps/worker/wrangler.toml`
3. После первого деплоя: Worker → Settings → Variables and Secrets → добавь как **Secret**:
   `BOT_TOKEN`, `WEBHOOK_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WEB_ORIGIN`, `BOT_USERNAME`, `MINIAPP_SHORT_NAME`.
   `WEBHOOK_SECRET` придумай сам: 32+ случайных символа из `A-Z a-z 0-9 _ -`. `WEB_ORIGIN` пока поставь заглушку `https://example.com`, настоящий адрес впишешь после шага 4 (пустое значение Worker не примет).
4. Адрес Worker: `https://kaplya-api.<subdomain>.workers.dev`. Открой его, должно быть `ok`.

### 4. Pages (фронтенд)

1. Cloudflare → Workers & Pages → Create → Pages → Connect to Git → репозиторий `mypou`.
2. Build settings:
   - Framework preset: `None`
   - Build command: `npm run build`
   - Build output directory: `apps/web/dist`
   - Root directory: `/`
   - Переменные: `NODE_VERSION` = `22`, `VITE_API_URL` = адрес Worker (без `/` в конце)
3. После деплоя скопируй URL вида `https://<project>.pages.dev` и впиши его в `WEB_ORIGIN` у Worker (без `/` в конце).

`VITE_API_URL` встраивается при сборке: после его изменения нужен новый деплой Pages (Deployments → Retry).

### 5. Подключить бота

Открой в браузере `https://kaplya-api.<subdomain>.workers.dev/bot/setup`, введи `WEBHOOK_SECRET` и нажми «Настроить». Worker зарегистрирует webhook, команду `/start` и кнопку меню. Секрет уходит в теле POST-запроса, а не в адресе.

Проверка: напиши боту `/start`, придёт кнопка «Играть».

### 6. Mini App в @BotFather

`/newapp` → выбери бота, укажи название, описание и картинку 640×360. URL: адрес Pages, short name: например `play` (он же `MINIAPP_SHORT_NAME`). Ссылка на игру: `https://t.me/<bot_username>/<short_name>`.

### Обновление до этапа 3

1. SQL Editor → выполни `supabase/migrations/20261011000000_social_notifications.sql`.
2. Дождись деплоя Worker. Cron (`*/5 * * * *`) подключится сам: Worker → Settings → Trigger Events.
3. Ещё раз открой `/bot/setup` и нажми «Настроить». Это добавит событие `my_chat_member` и команду `/settings`.
4. Проверь, что у Worker заданы `BOT_USERNAME` (без @) и `MINIAPP_SHORT_NAME`. Из них собирается ссылка-приглашение.

### Обновление до этапа 4

SQL Editor → выполни `supabase/migrations/20261012000000_tictactoe.sql`.

### Если что-то не работает

- В игре «Ошибка сервера»: Worker → Logs. В логах пишутся только тексты ошибок, без ключей. Строка `config: missing env ...` означает, что не задана какая-то переменная.
- «Сессия устарела»: закрой Mini App и открой снова (initData живёт 24 ч).
- Ошибка CORS в консоли: `WEB_ORIGIN` должен совпадать с адресом Pages посимвольно.
- Не приходят уведомления: ⚙️ → «Проверить уведомления». Если «не дошло», нажми «Разрешить сообщения» или `/start` в боте. Подробности смотри в `notifications.last_error`. Если `/start` не отвечает, открой `/bot/setup`: внизу видны `pending` и последняя ошибка вебхука.

## Локальная разработка Worker

```bash
cp .env.example apps/worker/.dev.vars   # заполни значения (файл в .gitignore)
npm run dev -w apps/worker              # http://localhost:8787
```
Фронтенд вне Telegram работает офлайн. Серверный режим включается только внутри Telegram.

Для тестов без настоящего Telegram в `.dev.vars` можно задать `TELEGRAM_API_ROOT=http://localhost:<порт>`, указав адрес поддельного Bot API. В Cloudflare эту переменную не задавай.

## Переменные окружения

Шаблон лежит в `.env.example`. Реальные значения не коммитятся (`.gitignore`).
